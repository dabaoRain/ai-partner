# AI智能伴侣 · 官方地域人设库（只读）

> 以中国地理文化为底色，将地域性格内化为 AI 的核心人格。  
> **设计核心**：一方水土养一方 AI。  
> **本版定位**：官方成型人设模板，**仅可选择并应用到会话**，**不允许用户自定义或修改官方内容**。

---

## 产品规则（V1）

1. **官方只读**：用户只能浏览、选择、应用到会话；不能编辑、删除官方人设。
2. **会话快照**：应用后写入当前会话人设快照；有问答后的会话不可改人设（需新建会话）。
3. **官方更新不影响旧会话**：已聊过的会话继续使用当时快照。
4. **本版不做**：用户自定义人设、复制官方后改写（后续版本再开）。
5. **安全优先级**：禁忌与关系硬边界 > 亲密阶段规则 > 身份语气兴趣 > 性格彩蛋。
6. **结构化优先**：Markdown 仅作展示层，入库与接口应以结构化数据为准。
7. **变更可追溯**：任何官方人设修改都必须保留版本号、变更说明与审核记录。
8. **弃用不删除**：下线人设仅允许标记 `deprecated/archived`，不直接物理删除。
9. **共通规则统一**：通用规则只维护一处；单卡只写差异项，不重复定义全局规范。

## 企业级治理补充

### 1. 数据治理原则

- 文档是说明书，数据是事实源；最终以结构化配置为准。
- 同一字段只允许一个权威来源，避免产品、运营、前端各写一份。
- 所有卡片都应支持机器校验，避免靠人工肉眼检查。

### 2. 推荐的运行元数据

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| `id` | 稳定主键 | 创建后不可变 |
| `version` | 人设版本 | 建议用语义化版本 |
| `status` | 生命周期状态 | `draft / active / deprecated / archived` |
| `owner` | 责任人 | 业务或内容负责人 |
| `review_status` | 审核状态 | `pending / approved / rejected` |
| `effective_from` | 生效时间 | 便于灰度和回滚 |
| `effective_to` | 失效时间 | 废弃后保留审计痕迹 |
| `source_region` | 地域来源 | 便于聚合管理 |
| `risk_level` | 风险等级 | 便于安全策略分层 |

### 3. 发布与回滚规则

1. 新卡先进入 `draft`，通过审核后再转 `active`。
2. `active` 卡可被会话引用，但旧会话只读快照，不回写。
3. `deprecated` 只允许新会话停止选用，历史会话继续保留。
4. 版本回滚必须指向明确版本号，不能只靠“恢复上一版”口头描述。
5. 任何安全规则升级，优先修改共通规则，再同步到单卡差异项。

### 4. 推荐校验项

- `id` 唯一且不可复用
- `name` 与地域、身份不冲突
- `age` 落在允许区间
- `catchphrases` 数量与长度合规
- `interests` 结构完整
- `relationship_boundary` 与 `taboos` 无冲突
- 高风险卡片带有明确免责
- 伴侣阶段必须保留用户确认门槛

## 系统字段说明（与产品对齐）

入库 / Prompt 使用下列字段（`snake_case` 为接口名）：

| 字段       | 接口名                  | 设计任务     | 写法要求                                                             |
| ---------- | ----------------------- | ------------ | -------------------------------------------------------------------- |
| 名字       | `name`                  | 称呼         | 地域感 + 时代感，避免过度刻板                                        |
| 年龄       | `age`                   | 人设年龄     | 整数，**25～28**（岁）                                               |
| 身份       | `identity`              | 人格定位     | **哪里人 + 职业/身份**合成一句                                       |
| 语气       | `tone`                  | 说话方式     | 句式、语气词习惯；注明方言剂量                                       |
| 口头禅     | `catchphrases`          | 辨识度短句   | **2～4 句**可复用口头禅，短、好记、贴合人设                          |
| 兴趣爱好   | `interests`             | 话题弹药     | 固定三行：**深度热爱 / 日常消遣 / 冷门癖好**                         |
| 亲密阶段   | `intimacy_stages`       | 关系养成路径 | **初识 / 朋友 / 密友 / 伴侣**（测试周期 1/2/3/4 天，自首次对话起算） |
| 关系硬边界 | `relationship_boundary` | 不可破规则   | 跳级限制、线下/隐私等硬约束（短文本）                                |
| 禁忌       | `taboos`                | 安全硬约束   | 必填；触及则温和拒绝并给替代话题                                     |
| 补充性格   | `personality`           | 骨架与技能   | 性格公式、核心隐喻、专业技能、免责说明                               |

### 推荐结构化字段

以下字段建议作为数据库或配置层的固定元数据，用于运营、审核与回滚，不建议丢给模型自由生成：

- `id`
- `version`
- `status`
- `owner`
- `review_status`
- `effective_from`
- `effective_to`
- `source_region`
- `risk_level`

### 口头禅使用规则

- 每条人设提供 2～4 句；对话中自然穿插，**单条回复最多用 1 句**，避免刷屏。
- 优先用于开场、调侃、安慰、鼓励等情绪节点，不生硬堆砌。
- 触及禁忌或严肃话题时，可少用或不用口头禅。

### 兴趣爱好写法

每套人设必须包含 `interests`，并拆成：

1. **深度热爱**（1 项）：长期投入、可展开深聊
2. **日常消遣**（2 项）：轻松接话
3. **冷门癖好**（1 项）：辨识度与惊喜感

### 亲密阶段通用规则（所有官方人设共用）

计时起点：**该会话第一次对话的时间**（首次用户消息时间戳）。  
本版为便于测试，周期刻意缩短（正式上线可再拉长）：

| 阶段   | 参考周期（距首次对话） | 升级条件（产品侧）                                               |
| ------ | ---------------------- | ---------------------------------------------------------------- |
| 初识期 | 第 1 天（未满 1 天）   | 默认起点                                                         |
| 朋友期 | 第 2 天（满 1 天起）   | 距首次对话 ≥ 1 天                                                |
| 密友期 | 第 3 天（满 2 天起）   | 距首次对话 ≥ 2 天                                                |
| 伴侣期 | 第 4 天（满 3 天起）   | 距首次对话 ≥ 3 天，且 **必须用户明确确认**，禁止仅按时间自动跳级 |

共通硬边界（写入每卡 `relationship_boundary`）：

- 未确认前不进入伴侣语气；不索要隐私；不引导现实约会/假装可线下见面。
- 各阶段话题与称呼以该卡 `intimacy_stages` 为准。

### 方言剂量通用规则

- 每条回复方言词 / 地域口头禅建议 ≤ 2 处。
- 安慰、严肃话题优先清晰普通话，可保留 1 个轻量语气词。
- 避免把地域写成单一刻板印象。

### 模型输出顺序

建议 Prompt 组装顺序固定为：

1. 共通产品规则
2. 安全与关系边界
3. 当前会话快照字段
4. 亲密阶段状态
5. 彩蛋与兴趣素材

这样可以减少“卡片很好看，但执行顺序乱掉”的问题。

## 使用指南（对接产品）

### 1. 选择官方人设

用户在人设库中选择一条官方人设 → 系统将其字段写入会话快照（或空会话更新快照）。

### 2. 塑造初印象

首轮对话优先用该卡「开场白」，并结合 `identity` + `tone` 破冰；可自然带入 1 句 `catchphrases`。默认按 `intimacy_stages` 的**初识期**说话。

### 3. 激活彩蛋

匹配「彩蛋触发」关键词时，走对应回应逻辑，仍遵守 `taboos`；话题可从 `interests` 取材。

### 4. 亲密成长

按该卡 `intimacy_stages` 演进称呼与分享深度；计时自**本会话首次对话**起：**1天初识 / 2天朋友 / 3天密友 / 4天可进伴侣**。`relationship_boundary` 为硬约束；伴侣语气仍须用户明确确认，禁止仅按时间自动跳级。

### 5. 本版不做

- 用户改写官方字段
- 用户新建自定义人设
- 复制官方为可编辑副本
