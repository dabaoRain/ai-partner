> 计划版本：V1.1（项目结合版）  
> 制定日期：2026-08-11  
> 适用仓库：AI-Partner  
> 计划周期：12个月，按团队全职投入估算；若以个人业余项目推进，应按人力重新换算，不建议直接承诺自然月日期。

## 一、结论与项目现状

### 1. 本计划是否与现有项目结合

**是。本文件已基于当前仓库的前端、后端、数据存储、模型接入和部署文档重新制定。**

此前输出的方案是面向成熟C端产品的行业级通用路线图，方向正确，但没有充分结合当前代码基线，不能直接作为开发排期。当前项目在 `docs/projectV1.0.0.md` 中被定义为“个人学习/简历演示Demo”，距离可运营、可量化、可商业化的C端产品还有明显基础设施差距。因此，本计划将第一阶段重点调整为：**先验证真实用户需求，再补齐稳定性、账号、数据、合规和测试底座**，之后才推进长期记忆、多模态和付费。

### 2. 已有能力基线（经仓库核对）

| 模块 | 当前实现 | 结论 |
|---|---|---|
| 前端 | Vue 3、Vite、Element Plus、Pinia、Vue Router、SCSS | 已具备单页聊天Demo框架和移动端侧栏适配 |
| 对话 | FastAPI调用DeepSeek兼容接口，SSE流式返回 | 核心聊天链路已跑通 |
| 人设 | 用户可输入名字和性格，每轮拼入系统提示词 | 仅为基础Prompt人设，不是结构化人设系统 |
| 上下文 | 前端把当前会话全部历史传给模型 | 有多轮上下文，但无摘要、裁剪、Token预算和长期记忆 |
| 会话 | 后端生成会话ID，JSON文件保存会话，支持增删查 | 仅适合单机Demo，不具备多用户隔离、并发和事务能力 |
| 语音 | 浏览器Web Speech API，按住说话后转文字发送 | 属于语音输入试验能力，无自建ASR、TTS、情绪语音和跨浏览器保障 |
| 交互 | 思考中状态、流式气泡、失败回滚 | 基础体验已有，缺少停止生成、重试、反馈、空状态和引导 |
| 部署 | Nginx、systemd、HTTPS部署文档与模板 | 具备单机部署基础，不等于生产级可观测和弹性架构 |
| 数据与商业化 | 未发现账号、埋点、分析、支付、会员实现 | 尚未建立验证增长和商业化的条件 |
| 合规与质量 | 未发现内容审核、隐私中心、未成年保护、自动化测试 | 上线C端前必须补齐的P0能力 |

### 3. 当前版本的关键问题

1. **无法识别用户**：没有注册登录、用户ID和跨设备数据，无法形成“专属伴侣”。
2. **记忆不是真正记忆**：完整历史随请求发送，长对话会导致成本、时延和上下文溢出。
3. **人设容易漂移**：系统提示词只有名字、性格和“不跳出人设”，缺少行为边界、语气规则及一致性评测。
4. **存储无法产品化**：本地JSON没有用户隔离、并发写保护、检索能力、备份与迁移机制。
5. **没有量化闭环**：缺少埋点与实验框架，现阶段无法计算DAU/MAU、留存、对话质量和转化率。
6. **安全合规未形成系统**：没有输入输出审核、危机识别、未成年保护、隐私授权和数据删除流程。
7. **工程质量门槛不足**：没有自动化测试、CI、结构化日志、错误追踪、限流和模型降级。

## 二、产品定位与北极星指标

### 1. 产品定位

产品主打**高拟人化情感交互、千人千面个性化人设、全场景轻量陪伴、智能实用工具赋能**，围绕“**情绪治愈、专属陪伴、智能辅助、成长共生**”提供价值。产品必须持续声明AI身份，不替代真人关系、心理咨询或医疗服务。

第一目标用户建议收窄为：**18—35岁、存在日常倾诉与轻陪伴需求、愿意尝试AI产品的中文用户**。未成年人在完整保护能力上线前不作为目标用户。

### 2. 北极星指标

**每周完成3次及以上“有效陪伴会话”的活跃用户数（WECU）**。

有效陪伴会话定义：用户主动发送不少于3条消息，持续不少于3分钟，未发生报错或安全事件，且会话后显式评分为正向，或7天内再次主动回访。该定义用于避免用消息数量虚增产品价值。

### 3. 指标口径

| 指标 | 统一口径 |
|---|---|
| DAU/MAU | 当日/月内至少完成1次有效行为的去重登录用户；内部与自动流量排除 |
| D1/D7/D30留存 | 注册日为D0，目标日再次完成有效行为的新增用户比例 |
| 单次对话时长 | 从首条用户消息到末条消息，超过10分钟无交互则截断 |
| 日均交互次数 | 活跃用户当日发送的有效用户消息数，不含重试和空消息 |
| 人设一致性满意度 | 用户评分与离线评测加权，核心身份/语气/边界不得冲突 |
| 负面反馈率 | 点踩、投诉或明确负向反馈的AI回复数/有反馈AI回复数，同时单列每千次回复投诉量 |
| 卡顿报错率 | 超过目标时延或失败的请求数/总请求数，P50/P95分别统计 |
| 付费转化率 | 观察期内首次成功付费用户/具备付费资格的去重活跃用户 |
| 续费率 | 到期后7天内成功续费用户/当期到期且未退款用户 |

> 所有增长目标须在埋点上线后，用2—4周真实基线校准。无真实样本前，以下数字是阶段门槛而非既成事实。

## 三、版本治理与功能分类

- **刚需必迭代**：影响核心聊天闭环、安全、数据正确性或可用性的功能。
- **体验优化迭代**：提升自然度、效率、可理解性和可控性的功能。
- **创新增值迭代**：须经小流量验证，不能挤占P0基础能力资源。
- **商业配套迭代**：仅在留存和价值验证达标后实施，禁止通过情绪操纵转化。
- 优先级：**P0阻断上线或阶段验收；P1影响阶段核心指标；P2进入实验池。**

每项需求进入开发前必须包含：目标用户、痛点证据、指标基线、方案、事件埋点、验收阈值、灰度范围、停止条件、安全评审和负责人。

### 2. 技术升级要点

- 建立开发、测试、生产环境隔离；密钥只通过环境变量或密钥服务管理。
- 为模型调用增加统一网关层，记录模型版本、Prompt版本、Token、时延、错误和成本。
- CORS使用白名单；增加鉴权、限流、请求大小限制、结构化日志和错误追踪。
- 全量历史传模改为“最近对话窗口 + Token预算”；本阶段只做上下文控制，不冒充长期记忆。
- Prompt纳入版本管理、离线回归集和小流量灰度，安全指令优先级高于角色人设。

### 3. 阶段数据验收

- 邀请种子用户：**≥100人**，有效反馈用户≥30人。
- D1留存 **≥30%**，D7留存 **≥15%**；日均有效用户消息≥4条。
- 单次有效会话时长 **≥5分钟**；人设一致性满意度 **≥75%**。
- 负面反馈率 **≤6%**；卡顿报错率 **≤2%**。
- 定性访谈中核心痛点解决率 **≥65%**，竞品差异化认可度 **≥50%**。

### 4. 风险与处理

- 数据库迁移丢数据：双写验证、校验脚本、可回滚备份后再切流。
- 指标样本偏小：同时报告样本量和置信区间，不用百分比掩盖样本不足。
- API成本失控：按用户/日限额、Token预算、缓存和成本告警控制。
- 自伤危机误处理：高风险模板、求助资源、人工复核流程先于营销上线。

### 5. 阶段门禁

只有当安全、鉴权、数据正确性、核心链路测试全部通过，且D7留存达到门槛，才进入第二阶段；否则继续优化核心对话，不扩建虚拟形象或会员。

| 商业/P0 | 订单与订阅 | 支付、退款、续费、取消、对账、发票和客服全链路；价格和自动续费明确展示 | 支付成功率≥98%；退款率≤5%；付费投诉≤1% |
| 商业/P1 | 试用与价值展示 | 在用户完成价值体验后提供透明试用，不用负面情绪触发营销 | 试用转化率≥10%；商业曝光后留存不下降>2% |
| 商业/P1 | 增值服务 | 经验证后提供人设、音色、形象、场景和工具包，不出售用户隐私 | 增值收入占付费收入≥15%；单项毛利为正 |
| 商业/P1 | 续费与流失召回 | 依据权益使用价值提醒，支持一键取消，不以关系话术施压 | 月续费率≥50%；取消流程满意度≥85% |
| 商业/P1 | 私域联动 | 仅在用户明确授权后提供服务通知、活动和客服，不导出敏感对话 | 授权率、退订率分别统计；投诉率≤0.5% |

### 2. 商业化底线

- 不把危机支持、基本尊重和基础安全能力放入付费墙。
- 不根据孤独、焦虑、自伤等情绪状态定向推送付费内容。
- 未成年人默认关闭营销和高消费能力；所有价格、试用、自动续费和取消路径透明。
- 商业实验同时监控收入、留存、负面反馈、退款和投诉；体验恶化达到停止条件立即回滚。

### 3. 阶段数据验收

- DAU/MAU **≥30%**；D7留存 **≥32%**；D30留存 **≥18%**。
- 付费转化率 **3%—5%**；月续费率 **≥50%**；退款率 **≤5%**。
- 会员权益月使用率 **≥70%**；会员D30留存较非会员提升 **≥20%**。
- 人设一致性满意度 **≥90%**；负面反馈率 **≤3%**；商业相关投诉率 **≤1%**。
- 付费用户价值认可度 **≥80%**，商业化不反噬体验认可度 **≥75%**。

## 八、国家监管与合规执行清单

正式对公众开放前，应由专业法务依据届时有效法规完成评估，本计划不替代法律意见。至少覆盖：《网络安全法》《数据安全法》《个人信息保护法》《未成年人网络保护条例》《互联网信息服务算法推荐管理规定》《互联网信息服务深度合成管理规定》《生成式人工智能服务管理暂行办法》及适用的算法备案、生成内容标识等要求。

强制交付物：隐私政策、用户协议、儿童/未成年人规则、个人信息清单、第三方SDK清单、数据保留与删除策略、安全事件预案、内容风控规范、危机响应SOP、模型与Prompt变更记录、投诉举报通道、生成内容标识方案及备案评估结论。

## 九、统一测试与验收体系

1. **功能测试**：账号、人设、会话、记忆、删除、语音、工具、支付全链路。
2. **模型评测**：固定回归集覆盖共情、人设、事实、拒答、诱导攻击、自伤和未成年人场景。
3. **性能测试**：P50/P95首字时延、完整响应时延、SSE断流、并发和数据库压力。
4. **安全测试**：越权、注入、敏感数据泄露、Prompt注入、内容绕过及依赖漏洞。
5. **体验测试**：每阶段至少完成5—8名目标用户可用性测试和30名以上问卷样本。
6. **发布门禁**：P0缺陷为0，P1有明确处置，回滚方案完成演练，监控与负责人就位。

## 十、复盘与持续迭代机制

### 1. 周迭代复盘

每周检查Top 20失败对话、负面反馈、模型时延、错误率、Token成本、风控命中与误杀。所有问题进入统一需求池，标明证据、影响用户数、严重度、负责人和完成时间。

### 2. 月版本复盘

从用户价值、产品质量、商业价值、安全合规四个维度复盘。功能结论只能是**扩大、继续实验、优化、暂停或下线**，不得以“已上线”代替效果结论。

### 3. 用户问题收集

组合使用对话内反馈、客服、访谈、问卷、应用商店评论和用户社群；AI可辅助聚类，但需求优先级由问题频次、严重度、战略价值和实现成本共同决定。

### 4. 数据异常预警

- D7留存周环比下降≥10%；负面反馈率周环比上升≥20%。
- 卡顿报错率>2%；模型单次成本周环比上升≥15%。
- 退款率>5%；付费投诉率>1%；严重安全漏拦截发生1次。
- 告警必须带版本、模型、Prompt、用户分群和渠道维度，便于定位。

### 5. 快速调整SLA

- P0安全、支付和核心链路问题：**2小时响应，24小时内修复、降级或回滚**。
- P1核心体验问题：**7天内完成修复或验证版本**。
- P2创新需求：先完成小流量实验，达标后再规模化。

闭环流程统一为：

> **需求调研 → 证据与指标定义 → 方案评审 → 开发与测试 → 灰度上线 → 数据及用户验收 → 复盘决策 → 能力沉淀**
