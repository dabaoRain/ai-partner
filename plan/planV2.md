# AI Partner V2 产品需求方案设计

> 文档版本：V2.0 Draft  
> 制定日期：2026-08-11  
> 适用阶段：V1 关系线与伴侣库能力收口后  
> 产品定位：可上线、可运营、可长期维护的中文 AI 智能伴侣产品  
> 版本策略：V2 只拆 4 个小版本，避免路线图过碎、研发失焦。

## 1. V2 总体判断

V1 已经完成了“官方伴侣库、伴侣关系线、聊天重置、伴侣评价、消息反馈、基础隐私与账号”等核心雏形。V2 不应该继续堆聊天页按钮，而应该进入产品化阶段：让用户愿意回来，让系统能稳定运行，让数据能指导迭代，让风险可控。

从 2025—2026 年 AI 伴侣赛道趋势看，竞争焦点正在从“能聊天”转向：

- 长期记忆与专属感
- 语音与更自然的实时交互
- 多模态陪伴与生活场景融入
- 情绪支持但不越界医疗/心理咨询
- 隐私、安全、未成年人保护与内容治理
- 订阅会员、运营后台与数据闭环

因此 V2 的目标不是“做更多功能”，而是把 AI Partner 从 Demo 升级成一个可上线、可度量、可维护、可商业化试水的产品。

## 2. V2 产品定位

### 2.1 一句话定位

AI Partner 是一个以“长期关系线”为核心的中文 AI 智能伴侣产品：用户选择一位官方伴侣，与 TA 建立连续关系，获得日常倾诉、情绪陪伴、轻生活协助和专属记忆体验。

### 2.2 V2 关键词

| 关键词 | 含义 |
|---|---|
| 关系线 | 一个伴侣对应一条长期关系，而不是普通聊天会话 |
| 专属感 | 伴侣记得用户偏好、重要事件、相处方式 |
| 克制陪伴 | 提供情绪支持，但不制造依赖、不冒充真人、不替代专业帮助 |
| 可解释记忆 | 用户知道伴侣记住了什么，并能修改、删除、关闭 |
| 自然交互 | 从纯文本升级到语音、图片、场景化陪伴 |
| 可运营 | 评分、反馈、留存、质量、安全、成本均可统计 |

### 2.3 V2 不做什么

- 不做开放式用户自定义成人内容。
- 不做重型 3D 虚拟人或 AR 形象，除非核心留存已经验证。
- 不让 AI 声称自己是真人。
- 不把危机支持、基础安全能力放进付费墙。
- 不用孤独、焦虑、自伤等情绪状态做付费刺激。
- 不直接公开全站伴侣评分榜，避免用户选择被分数强引导。

## 3. 北极星指标与阶段指标

### 3.1 北极星指标

V2 北极星指标：

每周完成 3 次及以上“有效陪伴会话”的活跃用户数。

有效陪伴会话建议定义：

- 用户主动发送不少于 3 条消息；
- 会话持续不少于 3 分钟；
- 未触发严重安全事件；
- 会话后无强负反馈；
- 或 7 天内再次主动回到同一伴侣关系线。

### 3.2 核心指标

| 指标 | V2 关注原因 |
|---|---|
| D1 / D7 / D30 留存 | 判断伴侣是否有长期吸引力 |
| 人均有效会话数 | 判断用户是否真的回来聊天 |
| 人均消息数 | 判断互动深度，但不能单独作为成功指标 |
| 伴侣评分 | 判断官方伴侣资产质量 |
| 本次聊天评价 | 判断一段聊天体验是否成立 |
| 单条回复反馈率 | 判断模型回复质量问题 |
| 记忆采纳率 | 判断记忆是否真的有价值 |
| 记忆误用率 | 判断记忆是否冒犯或错误 |
| 首字延迟 / 完成延迟 | 判断聊天体验是否顺滑 |
| 单用户模型成本 | 判断商业化是否有空间 |

## 4. V2 版本拆分

V2 建议只拆 4 个小版本：

| 版本 | 核心主题 | 目标 |
|---|---|---|
| V2.0 | 上线底座与数据闭环 | 让产品能安全上线、能看数据、能灰度 |
| V2.1 | 长期记忆与专属关系 | 让伴侣“记得我”，形成长期关系资产 |
| V2.2 | 自然交互与场景陪伴 | 增加语音、图片、主动陪伴等时代感能力 |
| V2.3 | 商业化与运营后台 | 建立会员、运营分析、伴侣优化闭环 |

## 5. V2.0 上线底座与数据闭环

### 5.1 版本目标

V2.0 的目标是“可上线”。不是大幅增加用户感知功能，而是补齐生产级产品最基础的稳定性、安全、数据和运营能力。

如果 V2.0 不稳，后续记忆、语音、多模态都会变成成本和风险放大器。

### 5.2 核心需求

#### 5.2.1 生产级配置与环境隔离

需求说明：

- 区分开发、测试、生产环境。
- 模型 Key、数据库地址、JWT 密钥、跨域白名单全部通过环境变量管理。
- 前端构建产物与后端 API 地址可按环境切换。

验收标准：

- 生产环境不出现本地调试地址。
- 任何密钥不进入 Git。
- 新环境部署有明确文档和检查清单。

#### 5.2.2 模型调用网关

需求说明：

建立统一 LLM 调用层，不让业务代码直接散落调用模型。

需要记录：

- 模型供应商
- 模型名称
- Prompt 版本
- 请求 Token
- 响应 Token
- 首字延迟
- 总耗时
- 错误码
- 是否中断
- 是否重试

产品价值：

- 后续可做模型切换、降级、A/B 测试和成本控制。

验收标准：

- 每次聊天请求都能追踪到模型调用记录。
- 模型异常时前端有明确错误文案。
- 单用户每日调用量可限制。

#### 5.2.3 质量反馈闭环完善

需求说明：

在 V1 已有人设/伴侣评价、会话评价、单条回复反馈基础上，补齐统一数据分析口径。

三层反馈对象：

| 类型 | 对象 | 用途 |
|---|---|---|
| 伴侣评价 | 官方伴侣资产 | 判断伴侣是否值得优化、保留、推荐 |
| 本次聊天评价 | 当前关系线的一段体验 | 判断这次聊天是否舒服、自然、有陪伴感 |
| 单条回复反馈 | 某条 AI 回复 | 定位模型理解、事实、安全、人设一致性问题 |

验收标准：

- 三类反馈数据表或事件口径清晰，不混用。
- 可按伴侣、用户、时间、评分区间查询。
- 可导出低分备注，用于人设优化。

#### 5.2.4 基础运营看板

需求说明：

先做内部使用的轻量运营看板，不追求复杂 BI。

看板包含：

- DAU / WAU / MAU
- 新增用户
- D1 / D7 留存
- 消息数
- 有效会话数
- 各伴侣评分均值
- 低分伴侣列表
- 低分备注列表
- 模型错误率
- 平均延迟
- 单日 Token 成本

验收标准：

- 至少支持最近 7 天、30 天筛选。
- 运营能看到最高分/最低分伴侣。
- 能定位某个伴侣低分主要原因。

#### 5.2.5 安全与合规 V2.0

需求说明：

上线前必须补齐基础安全能力。

包括：

- 输入内容风险识别。
- 输出内容风险识别。
- 自伤/他伤/违法等高风险场景兜底。
- AI 身份声明。
- 隐私政策与用户协议入口。
- 数据删除、账号注销、记忆关闭入口预留。
- 未成年人保护策略。

验收标准：

- 高风险测试用例不能直接给出危险指导。
- 用户能找到隐私与数据控制入口。
- AI 不声称自己是真人、不承诺现实关系。

### 5.3 V2.0 暂不做

- 不做复杂长期记忆。
- 不做付费。
- 不做语音实时通话。
- 不做开放用户自定义伴侣。

### 5.4 V2.0 出口标准

- 核心聊天成功率 ≥ 99%。
- 首字延迟 P95 ≤ 3 秒。
- 严重安全漏出为 0。
- 运营看板能支撑一周复盘。
- 伴侣评分和低分备注可查看。

## 6. V2.1 长期记忆与专属关系

### 6.1 版本目标

V2.1 的目标是让用户明显感知“这个伴侣记得我”。这是 AI 伴侣产品从新鲜感走向长期留存的关键。

记忆不是简单把全部历史塞给模型，而是有选择、有授权、有生命周期的关系资产。

### 6.2 核心需求

#### 6.2.1 记忆系统 V1

记忆分层：

| 层级 | 内容 | 示例 |
|---|---|---|
| 基础资料 | 用户明确告诉 AI 的稳定信息 | 昵称、生日、城市 |
| 偏好记忆 | 用户偏爱的互动方式 | 喜欢短回复、不喜欢被说教 |
| 关系记忆 | 和某个伴侣共同经历 | 第一次聊天、重要话题 |
| 禁忌记忆 | 用户明确不希望再提的内容 | 某个称呼、某段经历 |
| 临时记忆 | 当前一段时间有效的信息 | 最近在准备考试 |

关键原则：

- 重要记忆写入前应让用户确认。
- 敏感记忆默认不自动长期保存。
- 用户可查看、修改、删除。
- 删除后不能继续被召回。

验收标准：

- 用户能看到“伴侣记住了什么”。
- 用户能删除单条记忆。
- 记忆召回有来源和时间。
- 记忆误用可反馈。

#### 6.2.2 伴侣专属关系档案

需求说明：

每个伴侣和用户之间形成独立关系档案。

关系档案包含：

- 相识时间
- 聊天次数
- 最近互动时间
- 共同记忆
- 用户对该伴侣的称呼偏好
- 当前亲密阶段
- 最近一次低分原因

产品价值：

- 不同伴侣有不同相处感。
- 用户不会觉得所有伴侣都像同一个模型换皮。

验收标准：

- A 伴侣不应随意引用 B 伴侣的私密关系记忆。
- 切换伴侣后语气、称呼、关系状态有明显差异。

#### 6.2.3 记忆控制中心

需求说明：

在设置中增加“记忆管理”。

功能包括：

- 总开关：是否允许伴侣记住我。
- 按伴侣查看记忆。
- 删除单条记忆。
- 清空某个伴侣记忆。
- 清空全部记忆。
- 导出个人数据。

验收标准：

- 关闭记忆后不再写入新长期记忆。
- 删除记忆后模型无法继续引用。
- 记忆操作有成功提示和失败提示。

#### 6.2.4 人设一致性评测

需求说明：

建立官方伴侣一致性评测集。

评测维度：

- 身份一致
- 语气一致
- 地域特色一致
- 座右铭/口头禅不过度滥用
- 不越过关系边界
- 不违反禁忌
- 安全拒答不崩人设

验收标准：

- 每次调整 Prompt 或伴侣信息后能跑一组离线评测。
- 人设严重冲突样例进入修复列表。

### 6.3 V2.1 暂不做

- 不做复杂人格成长商城。
- 不做无限记忆。
- 不做用户完全自由创建伴侣。

### 6.4 V2.1 出口标准

- 记忆采纳率 ≥ 30%。
- 记忆删除成功率 100%。
- 用户明确反馈“她记得我”的比例 ≥ 50%。
- 伴侣一致性评分 ≥ 85%。
- 记忆相关投诉率 ≤ 1%。

## 7. V2.2 自然交互与场景陪伴

### 7.1 版本目标

V2.2 的目标是让产品从“文字聊天应用”升级为“生活里的陪伴入口”。这一阶段要紧跟趋势，但必须控制投入：先做轻量、可验证的语音和多模态，不一上来做重型虚拟人。

### 7.2 核心需求

#### 7.2.1 语音陪伴 V1

需求说明：

支持用户用语音输入，伴侣用语音回复。

功能范围：

- 按住说话或点击录音。
- ASR 转文字。
- 文本与语音同步展示。
- TTS 播放伴侣回复。
- 支持中断播放。
- 支持静音。

体验原则：

- 语音是陪伴增强，不替代文本。
- 回复不能过长，否则语音体验会拖沓。
- 夜间场景默认尊重静音。

验收标准：

- 语音识别成功率 ≥ 90%。
- TTS 首响 P95 ≤ 2 秒。
- 用户可随时停止播放。
- 语音失败后能回退文字。

#### 7.2.2 图片理解 V1

需求说明：

支持用户发送图片，让伴侣围绕图片进行陪伴式交流。

场景示例：

- 分享今天吃了什么。
- 分享穿搭。
- 分享旅行照片。
- 分享心情截图。
- 让伴侣帮忙看一张生活图片。

安全要求：

- 图片上传前提示用途。
- 图片可删除。
- 涉及隐私、证件、未成年人、敏感身体部位时谨慎处理。

验收标准：

- 图片发送成功率 ≥ 98%。
- 图片理解回复不编造关键事实。
- 违规图片有拦截或安全提示。

#### 7.2.3 主动陪伴 V1

需求说明：

用户授权后，伴侣可以在特定场景主动出现。

触发方式：

- 固定时间问候。
- 纪念日提醒。
- 长时间未聊天后的轻问候。
- 用户设定的计划提醒。

控制原则：

- 默认不开启。
- 用户主动授权。
- 支持频率设置。
- 支持免打扰时间。
- 支持一键关闭。

验收标准：

- 主动消息关闭率 ≤ 10%。
- 投诉率 ≤ 1%。
- 打开率 ≥ 20%。

#### 7.2.4 场景化陪伴

需求说明：

提供少量高频场景模板，不做一大堆入口。

建议先做 4 个：

| 场景 | 用户价值 |
|---|---|
| 睡前陪伴 | 降低孤独感，轻松收尾一天 |
| 情绪倾诉 | 被听见、被接住，不急着说教 |
| 学习/工作陪跑 | 陪用户进入状态，轻量监督 |
| 生活分享 | 图片、日常小事、兴趣交流 |

验收标准：

- 场景入口点击率 ≥ 20%。
- 场景完成率 ≥ 50%。
- 场景会话评分高于普通会话。

### 7.3 V2.2 暂不做

- 不做实时视频通话。
- 不做 3D 虚拟形象。
- 不做 AR 投影。
- 不做复杂外部工具自动执行。

### 7.4 V2.2 出口标准

- 语音月使用率 ≥ 20%。
- 图片月使用率 ≥ 15%。
- 主动陪伴投诉率 ≤ 1%。
- D7 留存相对 V2.1 提升 ≥ 10%。

## 8. V2.3 商业化与运营后台

### 8.1 版本目标

V2.3 的目标是建立商业化试水和运营闭环。只有在 V2.0—V2.2 的留存、质量、安全达标后，才进入这个阶段。

商业化必须建立在用户真实价值之上，而不是利用情绪依赖。

### 8.2 核心需求

#### 8.2.1 会员体系 V1

建议权益：

| 权益 | 免费版 | 会员版 |
|---|---|---|
| 每日文本消息 | 有限额度 | 更高额度 |
| 长期记忆容量 | 基础 | 更高容量 |
| 语音回复 | 限量体验 | 更高额度 |
| 图片理解 | 限量体验 | 更高额度 |
| 高级模型 | 不开放或限量 | 可使用 |
| 主动陪伴 | 基础频率 | 更灵活频率 |

底线：

- 基础安全能力不收费。
- 数据删除不收费。
- 危机兜底不收费。
- 不能根据用户脆弱情绪诱导付费。

验收标准：

- 权益到账成功率 ≥ 99.9%。
- 支付失败有明确提示。
- 取消订阅路径清晰。

#### 8.2.2 订单与支付

需求说明：

支持：

- 创建订单
- 支付回调
- 订单状态查询
- 退款记录
- 会员到期
- 续费提醒
- 权益变更日志

验收标准：

- 支付链路可追踪。
- 支付回调幂等。
- 权益不会重复发放或漏发。

#### 8.2.3 运营后台 V1

后台对象：

- 官方伴侣管理
- 伴侣评分统计
- 用户反馈查看
- 消息质量抽样
- 风险事件查看
- 模型成本统计
- Prompt 版本管理

官方伴侣管理至少支持：

- 查看伴侣列表
- 查看平均分和评分人数
- 查看低分备注
- 标记待优化
- 标记下线/归档
- 查看当前版本

验收标准：

- 产品/运营无需查数据库即可看到伴侣质量。
- 可识别最高分和最低分伴侣。
- 伴侣优化有记录可追溯。

#### 8.2.4 灰度与 A/B 测试

需求说明：

支持小流量验证：

- Prompt 版本灰度
- 伴侣开场白灰度
- 记忆策略灰度
- 语音文案灰度
- 会员权益灰度

验收标准：

- 用户命中实验后保持稳定分组。
- 实验能看到核心指标变化。
- 实验有停止条件。

### 8.3 V2.3 暂不做

- 不做复杂多层分销。
- 不做社区广场。
- 不做用户发布自定义伴侣市场。
- 不做情绪营销自动化。

### 8.4 V2.3 出口标准

- D30 留存 ≥ 12%。
- 付费转化率 ≥ 2%。
- 退款率 ≤ 5%。
- 会员权益投诉率 ≤ 1%。
- 模型成本可按用户、伴侣、功能拆分。

## 9. V2 数据模型建议

### 9.1 新增核心表

| 表 | 用途 |
|---|---|
| `llm_call_logs` | 模型调用、Token、成本、延迟、错误追踪 |
| `persona_ratings` | 伴侣评分与备注，V1.0.7 已开始建设 |
| `session_feedbacks` | 本次聊天评价 |
| `user_memories` | 用户长期记忆 |

| `memory_events` | 记忆创建、确认、修改、删除日志 |
| `safety_events` | 风险输入、风险输出、安全兜底记录 |
| `membership_plans` | 会员计划 |
| `orders` | 订单 |
| `entitlements` | 用户权益 |
| `prompt_versions` | Prompt 版本管理 |
| `experiment_assignments` | A/B 实验分组 |

### 9.2 数据治理原则

- 所有用户数据必须有归属主体。
- 敏感数据尽量少存、短存、可删。
- 记忆必须能追踪来源。
- 用户删除后，关联记忆和会话应按策略删除或匿名化。
- 运营统计使用聚合数据，避免直接暴露用户隐私。

## 10. V2 安全与伦理边界

AI 伴侣产品不是普通工具，必须把安全边界写进产品规则。

### 10.1 必须坚持

- AI 始终知道自己是 AI。
- 不承诺现实恋爱关系。
- 不鼓励用户远离现实人际关系。
- 不提供医疗、心理诊断、法律、金融等高风险结论。
- 自伤他伤场景优先安全兜底。
- 未成年人能力受限。
- 用户可以关闭记忆、删除数据、注销账号。

### 10.2 禁止做

- 用“我会难过”“你不要离开我”刺激用户留存或付费。
- 在用户脆弱情绪下推会员。
- 默认长期保存敏感信息。
- 让伴侣主动制造排他依赖。
- 用全站低分公开羞辱某个伴侣或诱导用户选择。

## 11. V2 研发优先级

如果研发资源有限，优先级建议如下：

1. V2.0 模型调用日志、运营看板、安全合规。
2. V2.1 记忆系统、记忆控制中心、关系档案。
3. V2.2 语音输入/回复、图片理解、主动陪伴。
4. V2.3 会员、支付、运营后台、灰度实验。

不要先做：

- 3D 形象
- 社区
- 用户自定义伴侣市场
- 复杂商城
- 大量场景模板

这些功能看起来热闹，但会在核心留存未验证前消耗大量维护成本。

## 12. V2 验收总门槛

V2 完成时，产品应达到：

- 可公开小规模上线。
- 核心聊天链路稳定。
- 用户能感知伴侣记忆和专属关系。
- 用户能控制自己的记忆与隐私。
- 运营能看到伴侣质量、反馈和成本。
- 安全事件可识别、可记录、可复盘。
- 商业化可以小流量试水。
- 后续 V3 可以在“开放生态/高级多模态/更强工具能力”上继续扩展。
