# V1.0.6 伴侣关系线交互优化

> 将前端心智从「新建会话」进一步收口为「选择伴侣 / 开始关系 / 继续聊天 / 清空记录」。

## 产品判断

当前产品属于**智能伴侣关系线**，不是普通多会话聊天工具。因此前端不应把主流程表达为「新建会话」，而应围绕「伴侣」和「关系线」组织。

## 交互原则

1. **删除侧栏顶部主按钮**  
   不再把「选择伴侣 / 开始聊天 / 打开对话 / 重置对话」塞进同一个顶部入口。

2. **主聊天区负责开始关系**  
   选中伴侣但尚未开聊时，主区展示明确 CTA：`开始和 TA 聊天`。

3. **聊天头部不展示 session_id**  
   面向用户展示伴侣姓名与短副标题，弱化工程化会话编号。

4. **名字下方只展示短信息**  
   标准格式为 `座右铭`；不展示完整身份，不展示籍贯，不展示开场白。

5. **侧栏列表表达为我的伴侣**  
   列表展示头像、姓名、籍贯，弱化「历史文档」感。

6. **左下角入口表达为伴侣库**  
   伴侣库入口只承担选择/更换功能，不重复展示当前伴侣头像、籍贯、身份或开场白。

7. **官方伴侣弹层自动定位使用中伴侣**
   每次打开弹层时，优先将正在使用中的伴侣滚动到左侧伴侣库可视区域。

8. **单个伴侣操作进入三点菜单**  
   左侧「我的伴侣」列表项右侧使用三点菜单承载针对该伴侣的操作。

9. **删除文案改为清空聊天记录**  
   当前版本后端仍为物理删除会话，但前端文案收敛为「清空记录后可重新开始」。

10. **输入框按关系状态变化**  
   未选伴侣时禁用输入；已选未开始时提示对当前伴侣说第一句话。

11. **空态承担第一步引导**  
   未选伴侣时，主聊天区直接提供 `选择伴侣` CTA；已选未开始时，主聊天区提供 `开始和 TA 聊天` CTA。

12. **伴侣评价独立于单条消息反馈**
   伴侣评价用于衡量“这位伴侣整体是否值得继续相处/优化/保留”，不替代单条回复的质量反馈。

## 本版改动

### 侧栏

- 删除顶部 `选择伴侣` 主按钮，避免与底部伴侣入口重复。
- 「我的伴侣」列表展示头像、姓名、籍贯。
- 不展示开场白、最近消息或完整身份，避免与主区和消息区重复。
- 列表项右侧从直接清空按钮改为三点菜单。
- 三点菜单支持：
  - `清空并重开`：清空该伴侣聊天记录，重新生成开场白并打开新关系线。
  - `清空聊天记录`：清空该伴侣聊天记录，保留当前伴侣选择，可重新开始。
- 左下角入口改为 `伴侣库`，摘要为 `查看或更换官方伴侣 / 挑选一位官方伴侣`。
- 菜单中的破坏性操作统一使用 `清空聊天记录` 语义。

### 主聊天区

- 头部从 `当前对话: session_id` 改为展示短副标题。
- 名字下方标准展示：`座右铭`。
- `座右铭` 来自人设字段 `motto`，不是开场白截断，也不是完整身份。
- 完整身份只保留在人设详情弹窗，不放在聊天头部。
- 籍贯只保留在左侧列表和人设详情，不放在聊天头部。
- 开场白只保留在消息区，不放在聊天头部或伴侣库入口。
- 未开始关系时，空态说明改为「发出第一句话后，会建立你们的专属关系线」。
- 未选伴侣时，空态提供 `选择伴侣` 按钮。
- 已选伴侣未开聊时，展示 `开始和 TA 聊天` 按钮。
- 输入框 placeholder 区分：
  - 未选伴侣：`请先选择伴侣`
  - 已选未开始：`对某某说第一句话...`
  - 已建立关系：`想跟某某说点什么...`

### 伴侣弹窗

- 头部文案从「官方人设」改为「官方伴侣」。
- 左侧列表标题从「人设库」改为「伴侣库」。
- 打开弹层后自动将 `使用中` 伴侣滚动到伴侣库可视区域。
- 底部提示改为「已有关系线会继续聊天，没有则进入待开始状态」。
- 主按钮按状态显示 `选择这位伴侣 / 继续当前伴侣`。
- 底部新增 `评价伴侣` 入口，进入独立评价弹层。
- 评价弹层使用 Element Plus `el-rate` 五星评分组件，满分 5 分、最低 1 分。
- 评价弹层支持填写备注信息，用于记录用户对性格、语气、陪伴感、地域特色等维度的主观反馈。
- 评分不常驻展示在伴侣列表中，避免用户在选择前被分数强暗示。

### 反馈体系

- 单条消息反馈关注“这一句回复是否有帮助/是否符合预期”。
- 伴侣评价关注“这个伴侣整体体验是否成立”。
- 两类反馈数据分表存储，避免后续统计口径混乱。
- 同一用户/游客对同一伴侣只保留一条伴侣评价，重复提交时更新原记录。

### 接口字段

- `/sessions` 列表补充 `avatar_url`，供前端伴侣列表稳定展示头像。
- 新增 `motto` 字段：Markdown 人设、数据库、会话快照、API 响应、前端规范化与 Prompt 均同步支持。
- 新增 `persona_ratings` 数据表，围绕 `persona_id` 存储伴侣评分与备注。
- 新增 `GET /personas/{persona_id}/rating`：读取当前用户/游客对该伴侣的评价。
- 新增 `POST /personas/{persona_id}/rating`：提交或更新该伴侣评价，字段为 `score`（1～5）与 `remark`。

## 待后端升级

1. 聊天接口不应再依赖前端传完整人设快照与历史消息，后端应从会话快照与消息表组装 Prompt。
2. 人设锁定条件建议从「任意消息」改为「首条用户消息」。
3. 一人设一关系线建议增加数据库唯一约束：`owner_type + owner_id + persona_id`。
4. 删除建议升级为三层语义：`归档关系 / 清空聊天记录 / 永久删除`。
5. 删除会话前应检查是否有该会话的流式生成任务正在进行。
