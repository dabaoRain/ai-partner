## 这次要更新什么？

V1.0.4 同时改了：

| 部分 | 内容                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 后端 | 官方人设库、开场白、美图路径、`persona/index.md` 种子逻辑                     |

所以这次是 **前端成品 + 后端源码 + 人设图** 一起更新，不是只传 `dist`。

```text
本机改动（代码 + images）
    → 本机构建前端 front/dist
    → rsync 源码到服务器 /opt/ai-partner/
    → rsync dist 到服务器 /var/www/ai-partner/dist/
    → 服务器重启后端（自动种子人设 + 拷贝美图）
    → 浏览器验证
```

## 步骤 2：上传源码到服务器 `/opt/ai-partner`

回到**项目根目录**（注意：是 `AI-Partner`，不是 `front`）：

```bash
cd /Users/shaohaibin/项目/AIAgent/Python/AI-Partner
pwd
# 末尾应是 .../AI-Partner
```

执行上传（把 IP 换成你的）：

```bash
rsync -avz \
  --exclude 'front/node_modules' \
  --exclude 'front/dist' \
  --exclude 'back/.venv' \
  --exclude 'back/.env' \
  --exclude 'back/sessions' \
  --exclude 'back/data' \
  --exclude 'back/static' \
  --exclude 'back/__pycache__' \
  --exclude '**/__pycache__' \
  --exclude '.git' \
  ./ root@47.xx.xx.xx:/opt/ai-partner/
```

### 为什么要排除这些？

| 排除项                             | 原因                                      |
| ---------------------------------- | ----------------------------------------- |
| `front/node_modules`、`front/dist` | 太大；成品另传到 Nginx 目录               |
| `back/.venv`                       | 虚拟环境在服务器自己装，不要覆盖          |
| `back/.env`                        | **服务器上的 API Key，绝不能被本机覆盖**  |
| `back/sessions`、`back/data`       | 服务器上的聊天/数据库，不要用本机数据覆盖 |
| `back/static`                      | 美图由后端启动时从 `images/` 自动同步生成 |
| `.git` / `__pycache__`             | 无用、易冲突                              |

上传成功时，终端会出现很多文件名；其中应能看到类似：

- `images/1.jpg` … `images/15.jpg`
- `persona/index.md`
- `back/persona_seed.py`
- `front/src/components/chat/PersonaAvatar.vue` 等

### 上传后快速检查

```bash
ssh root@47.xx.xx.xx "ls /opt/ai-partner/images | head; ls /opt/ai-partner/images | wc -l; ls /opt/ai-partner/persona/index.md; ls /opt/ai-partner/back/persona_seed.py"
```

期望：`images` 约 15 个 jpg；`persona/index.md` 与 `persona_seed.py` 存在。

## 步骤 3：上传前端成品到 Nginx 目录

仍在本机、项目根目录：

```bash
cd /Users/shaohaibin/项目/AIAgent/Python/AI-Partner

# 先确认本地产物在
ls front/dist/index.html

rsync -avz --delete front/dist/ root@47.xx.xx.xx:/var/www/ai-partner/dist/
```

说明：

| 参数       | 作用                                                 |
| ---------- | ---------------------------------------------------- |
| `-avz`     | 归档、可读输出、压缩传输                             |
| `--delete` | 删掉服务器上本地已不存在的旧资源（避免旧 hash 残留） |
| 末尾 `/`   | 传「目录里的内容」，不要再套一层文件夹               |

一般**不用**重启 Nginx。

确认服务器上已是新文件：

```bash
ssh root@47.xx.xx.xx "ls -la /var/www/ai-partner/dist && ls /var/www/ai-partner/dist/assets | head"
```

## 步骤 4：服务器上修正权限并重启后端

SSH 登录服务器：

```bash
ssh root@47.xx.xx.xx
```

后端进程用 `www-data` 用户跑，刚 `rsync` 上去的文件可能是 `root` 属主，需要改一下，否则写 `static/personas` 或读代码可能出问题：

```bash
# 保证后端目录可被服务用户使用（不要动坏 .env 权限）
sudo chown -R www-data:www-data /opt/ai-partner/back
sudo chmod 600 /opt/ai-partner/back/.env

# 人设图源目录给后端读（在仓库根 images/）
sudo chown -R www-data:www-data /opt/ai-partner/images
sudo chown www-data:www-data /opt/ai-partner/persona/index.md
```

**V1.0.4 必须装依赖**（相对更早版本新增了 `SQLAlchemy` / `PyJWT` / `bcrypt` 等）。漏装会出现 `ModuleNotFoundError: No module named 'sqlalchemy'`，Nginx 报 **502**：

```bash
cd /opt/ai-partner/back
.venv/bin/pip install -r requirements.txt
```

重启后端（启动时会 `init_db()` → 种子官方人设 → 把 `images/*.jpg` 拷到 `back/static/personas/`）：

```bash
sudo systemctl restart ai-partner-api
sudo systemctl status ai-partner-api --no-pager
```

期望看到 `active (running)`，且没有一堆红色报错。

看最近日志（确认启动成功）：

```bash
sudo journalctl -u ai-partner-api -n 40 --no-pager
```

检查美图是否已生成：

```bash
ls -la /opt/ai-partner/back/static/personas/ | head
ls /opt/ai-partner/back/static/personas/*.jpg | wc -l
# 期望：15
```

若 `static/personas` 为空或不存在：

1. 确认 `/opt/ai-partner/images/` 里真有 jpg
2. 再看日志有没有权限错误
3. 修好后再次 `sudo systemctl restart ai-partner-api`

本机健康检查：

```bash
curl -s http://127.0.0.1:8000/health
# 期望类似：{"status":"ok","has_api_key":true}

curl -s http://127.0.0.1:8000/personas | head -c 400
# 期望能看到人设 JSON，且 avatar_url 类似 /static/personas/1.jpg
```

测一张头像（后端静态挂载）：

```bash
curl -sI http://127.0.0.1:8000/static/personas/1.jpg | head
# 期望有 HTTP/1.1 200
```

测完可 `exit` 离开服务器。

## 一键命令（复制用）

把 `47.xx.xx.xx` 换成真实 IP 后，在 **Mac、项目根目录**按顺序执行：

```bash
# —— 本机 ——
cd /Users/shaohaibin/项目/AIAgent/Python/AI-Partner/front \
  && pnpm build \
  && cd .. \
  && rsync -avz \
    --exclude 'front/node_modules' \
    --exclude 'front/dist' \
    --exclude 'back/.venv' \
    --exclude 'back/.env' \
    --exclude 'back/sessions' \
    --exclude 'back/data' \
    --exclude 'back/static' \
    --exclude 'back/__pycache__' \
    --exclude '**/__pycache__' \
    --exclude '.git' \
    ./ root@47.xx.xx.xx:/opt/ai-partner/ \
  && rsync -avz --delete front/dist/ root@47.xx.xx.xx:/var/www/ai-partner/dist/

# —— 服务器 ——
ssh root@47.xx.xx.xx 'bash -s' <<'EOF'
set -e
chown -R www-data:www-data /opt/ai-partner/back
chmod 600 /opt/ai-partner/back/.env
chown -R www-data:www-data /opt/ai-partner/images
chown www-data:www-data /opt/ai-partner/persona/index.md
cd /opt/ai-partner/back && .venv/bin/pip install -r requirements.txt
systemctl restart ai-partner-api
systemctl is-active ai-partner-api
ls /opt/ai-partner/back/static/personas/*.jpg | wc -l
curl -s http://127.0.0.1:8000/health
EOF
```

最后再按「步骤 5」用浏览器点一遍。

## 常见问题

| 现象                          | 处理                                                                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm build` 失败             | 先 `pnpm i`；确认 Node 18+                                                                                                               |
| `rsync` 连不上                | 检查 IP、SSH 密钥/密码、安全组是否放行 22                                                                                                |
| 页面还是旧的                  | 看 rsync 是否真传成功；再 `Cmd+Shift+R` 或无痕窗口                                                                                       |
| 接口 502 / `activating`       | 后端崩了：`journalctl -u ai-partner-api -n 80`；常见缺包 → `cd /opt/ai-partner/back && .venv/bin/pip install -r requirements.txt` 后重启 |
| 人设列表空 / 接口 500         | `journalctl -u ai-partner-api -n 80`；确认 `persona/index.md` 已上传                                                                     |
| 头像裂图 / 404                | 看服务器 `ls /opt/ai-partner/back/static/personas/`；没有则查 `images/` 与权限后重启服务                                                 |
| 重启后 Key 没了 / 模型不可用  | 多半误覆盖了 `.env`；重新在服务器编辑 `back/.env`，`chmod 600`，再 `restart`                                                             |
| 聊天记录突然没了              | 多半同步时覆盖了 `back/data`；以后务必带上 `--exclude 'back/data'`                                                                       |
| `Permission denied` 写 static | 再执行 `chown -R www-data:www-data /opt/ai-partner/back` 后重启                                                                          |
